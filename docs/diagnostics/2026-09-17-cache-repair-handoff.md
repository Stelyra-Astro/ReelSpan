# Build 12 缓存故障修复交接（待 Build 13 验收）

> 此文保留 ZIP 交接时的历史状态。后续生产部署、Xcode 验证及发布结果以 `docs/releases/BUILD13_VALIDATION.md` 为准；下文“未部署/未编译”不再作为当前状态。

依据 `2026-09-17-build12-cache-startup.md` 和本次上传的 `ReelSpan-main (2).zip` 修改。该文件记录本地源码改动，不代表当前线上 RPC 已更新，也不代表 App 已编译/上传。

## 根因与已改动

- 线上默认浏览 `reelatlas_discover` 在匿名角色 `statement_timeout=3s` 下返回 HTTP 500/PostgREST 57014。根因是分页之前对整库做元数据、地点、时期连接和排序。客户端此前 network-first，失败再找「同一语言/筛选/排序/页」缓存；Build 11 的 SQLite 和 `MovieMetadata-v1` 不是新版目录页缓存，因此升级后即使本地有 50,005 条故事关系，也会首屏空白。
- 目录页读取改为先尝试精确键缓存；成功后后台刷新。缓存从可清理的 Caches 迁到 Application Support，首次读取时合并旧页快照；页快照不再按 60 页裁剪，且不设置到期日。请求无可用缓存时才走网络，SQL 超时码 57014 不做无意义的即时重试。
- 旧版迁移可从 `MovieMetadata-v1` 枚举已缓存的 TMDB 影片元数据，容许过期条目作为离线副本；SQLite 用当前地点/时间过滤匹配 ID，再用真实片名/海报等信息展示。显示时标注“已保存影片”，不会把局部样本当完整 5 万条目录、把 QID 当片名或把其他筛选页冒充结果。SQLite 新增 TMDB ID 索引，旧数据库在迁移时原位建索引；不删除用户数据。
- 已显示电影和图钉不因故事同步批次、无变化的 iCloud 恢复或同页刷新失败而清空；首次故事库初始化失败会在持续前台自动重试。收藏列表不再在本地数据返回前等待评分 RPC。Where 分组缺关联时降级显示已有电影并定时补取；顶部数量取本地已下载和 manifest 总量较大者，避免 49,995 小于设备实际 50,005 的明显错误。

## 尚需执行的服务端操作

`supabase/migrations/202609170001_discover_fast_browse.sql` **只是候选迁移，尚未部署或在生产 PostgreSQL 执行验证**。它保留原函数作为 `reelatlas_discover_search`，给无搜索、无筛选的 `recommended` 与 `country:<QID>` 增加先按 ID 分页、再仅关联单页元数据的分支，其余调用委托原函数。执行前应检查当前云端函数签名、返回列、依赖、已有同名函数以及 migration 记录，并在事务/测试库中先验证。它不能证明搜索、时间/地点/类型筛选和其他排序的 RPC 均已提速。

部署后用匿名 publishable key 分别测 `recommended`、`country:Q30`、关键词、年份、国家/城市、类型、其他排序和下一页；确认状态 200、16 条数据及分页顺序正确，耗时低于匿名角色 3 秒超时预算，并在真机冷启动/离线/前后台切换下复测。**仅发布 iOS ZIP 不会改变服务器上已确认的超时。**

## 验收边界

首次全新安装仍需网络才能取得 manifest、首批故事、其所引用的父表与可显示元数据；现在先下载首批 250 部影片的地点、匹配及必要的父记录并发布本地 SQLite，其他父表、概念和剩余影片在后台增量补齐。不能承诺无本地数据时离线展示，或在目录 RPC 仍超时时保证首批影片均有可显示的片名/海报。旧机若元数据文件完全没有缓存，故事 SQLite 单独只含 QID，无法离线生成真实电影名称；这一场景只能等待目录或元数据服务恢复。所有依赖 iOS/MapKit 的集成测试和实际 Supabase 生产 EXPLAIN，需要在 Xcode/服务端另行验证。

## 地图与永久本地缓存（本次继续完善）

- 默认进入 Map，切换控件顺序为 Map / List；地图使用原生平面、弱化底图并隐藏 POI/交通图层。
- 地图底部按钮显示 `地点 · N films`；N 从设备 `Application Support/ReelAtlas/content.sqlite` 对当前地点、年份及收藏条件做不重复的完整电影计数，绝不使用首屏页大小推算 `15+`。本地同步尚未完成时明确写 `saved films`；搜索、类型和时期 QID 等无法从现有 SQLite 保证全量精确过滤的情况不显示臆测数字。
- 结果 sheet 向下完全关闭后只保留独立的底部深色按钮；再次点击按钮重新展开。本地 SQLite 已算出精确数量时，即使发现页/元数据仍未加载，底部入口也会保留。
- 故事 SQLite、地点目录快照、发现页快照与已下载影片元数据均放置/迁移至 Application Support，不按日期过期；内容同步只增量更新本地 SQLite，不因请求失败清空。图片等可再取回的数据仍保留独立空间预算，用户主动清理缓存及卸载 App 不在持久保留承诺内。
- 本机已验证：Python `Tests/ProjectMergeTests` 55 例；Swift 可独立编译的 SQLite 精确计数集成测试 5 例；缓存元数据经旧时间戳、小图片预算和重新实例化后可读取；抽屉收起/重开与非推算数字标签的 Swift 独立执行检查。同步集成测试还通过临时 Linux CryptoKit/Networking 兼容桩执行了既有回归和新增的“首批仅下载所需父表”场景（桩不随产品交付）。Linux 无 Apple CoreLocation/MapKit，尚不能代替 Xcode 真机编译或线上 PostgreSQL EXPLAIN。服务端 SQL 仍未部署。
